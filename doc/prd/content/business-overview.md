# Content 业务总览

## 1. 模块定位

`content` 模块是社区内容系统的底层业务服务，按类 V2EX 的社区主题模型设计。它不负责页面展示聚合，而负责维护内容事实、状态机、互动事实、浏览审计、治理审计和事件投递。

| 业务域 | 核心对象 | 目标 |
| --- | --- | --- |
| 分类导航 | domain、tag | 支撑首页分类导航、节点页、文章快速筛选 |
| 文章主题 | article、postscript、article action、view record | 支撑普通主题发布、浏览、互动、附言、归档、治理 |
| 评论讨论 | comment、comment action | 支撑顶级评论、父子回复、评论互动、评论治理 |
| 内容治理 | moderation record | 支撑管理端对文章、评论、附言进行审计化处置 |
| 事件投递 | outbox event | 支撑通知、积分、搜索、推荐等模块异步消费内容事实 |

## 2. 分期目标

| 阶段 | 实现目标 | 说明 |
| --- | --- | --- |
| P0 | 普通主题核心闭环 | 完成普通文章、分类、评论、互动、浏览审计、治理、Outbox |
| P1 | 类型扩展与积分相关能力 | 完成问答、打赏增强、抽奖、投票、专栏 |
| P2 | 复杂分发能力 | 完成搜索、推荐、热度、个性化内容流 |

## 3. P0 功能范围

| 模块 | P0 功能 | 不做内容 |
| --- | --- | --- |
| Domain/Tag | 分类创建、更新、查询、启停、排序、文章数同步维护 | 复杂推荐分类、跨 domain tag |
| Article | 创建草稿、编辑草稿、发布草稿、归档、私有/公开、查询、浏览 | 发布后编辑正文、匿名发帖、非 normal 类型开放 |
| Article Tag | 独立绑定、解绑、查询文章 tag | 混入草稿创建/编辑接口 |
| Postscript | 作者发布后追加附言、查询附言 | 附言编辑、归档文章添加附言 |
| Comment | 顶级评论、回复评论、线程查询、时间线、最新回复 | 评论收藏、评论打赏、评论关注 |
| Interaction | 文章点赞/收藏/感谢/打赏，评论点赞/感谢 | 关注、评论收藏、评论打赏 |
| View Audit | Redis 去重、浏览量增量、登录态浏览历史 | 游客浏览历史落库 |
| Moderation | hide/unhide/lock/unlock/delete/restore/archive/unarchive 审计 | reason code 字典 |
| Outbox | 内容事实事件、事务后即时投递、scheduler 补偿 | exactly-once 投递 |

## 4. P1 功能范围

| 功能 | 实现方式 | 设计理由 |
| --- | --- | --- |
| QA 问答 | `content_article_qa` 扩展表 | 问答有悬赏、采纳、结算等独有字段，不污染文章主表 |
| 打赏增强 | 打赏记录、积分结算事件、打赏区解锁闭环 | 打赏是积分相关业务，需要与积分服务通过事件解耦 |
| 抽奖 | 抽奖配置、参与记录、中奖记录、开奖任务 | 抽奖有参与和开奖审计，必须独立建模 |
| 投票 | 投票配置、选项、投票记录、结果统计 | 投票需要选项和投票唯一约束，不适合塞入文章主表 |
| 专栏 | 专栏、专栏文章、成员、订阅 | 专栏不是 tag，它有作者、目录、协作者和订阅关系 |

## 5. P2 功能范围

| 功能 | 说明 |
| --- | --- |
| 全文搜索 | 基于文章标题、正文、domain、tag 建索引 |
| 搜索索引同步 | 消费 content outbox 事件更新搜索服务 |
| 热度排序 | 根据浏览、评论、点赞、收藏、时间衰减计算 |
| 推荐流 | 基于用户浏览、互动、tag 偏好进行召回 |
| 内容分发 | Feed、个性化推荐、屏蔽过滤、运营干预 |

## 6. 核心边界

### 6.1 Content 负责

| 职责 | 说明 |
| --- | --- |
| 内容事实 | 文章、评论、附言、分类、互动、浏览记录 |
| 状态机 | 文章生命周期、治理限制、评论状态 |
| 作者权限 | 作者是否可编辑、发布、归档、添加附言、删除评论 |
| 分类计数 | 文章绑定/解绑 tag 时同步维护 `article_count` |
| 互动幂等 | 同一用户对同一目标同一 action 只能有一条有效记录 |
| 浏览去重 | 通过 Redis 对 24h 内重复浏览去重 |
| 审计记录 | 治理、浏览历史、互动事实 |
| Outbox | 将内容事实变化异步通知其他模块 |

### 6.2 BBS 负责

| 职责 | 说明 |
| --- | --- |
| HTTP 适配 | 对外接口、参数校验、登录态注入 |
| 展示聚合 | 作者资料、tag/domain、评论预览、互动状态 |
| Markdown 渲染 | 文章、附言、评论展示内容渲染 |
| 列表裁剪 | 对 content 返回的完整事实进行摘要、封面提取、展示模型封装 |
| 多 RPC 编排 | 根据页面需求多次调用 content/user 等服务组装响应 |

## 7. 总体设计理由

- `content` 是底层服务，必须保护核心状态和权限，不能完全依赖 BFF 做过滤。
- BFF 只做展示聚合，可以避免 `content` 被具体页面模型绑死。
- P0 只开放 `normal` 文章，能先稳定社区主题主链路。
- 文章类型扩展使用独立表，避免文章主表随着业务增长变成大杂烩。
- 浏览量和互动计数是高频读字段，需要冗余，但必须保留审计与补偿能力。
- Outbox 采用 at-least-once，消费者按 `event_id` 幂等，成本和可靠性更平衡。
