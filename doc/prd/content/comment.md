# Content Comment 业务设计

## 1. 业务定位

评论系统承载文章下的讨论。P0 支持顶级评论、父子回复、多种查询组织方式、点赞、感谢、删除和治理。

## 2. P0 功能

| 功能 | 使用方 | 说明 |
| --- | --- | --- |
| 创建顶级评论 | BBS | 用户对文章直接评论 |
| 回复评论 | BBS | 用户回复某条评论 |
| 评论线程 | BBS | 按顶级评论组织楼中楼 |
| 回复列表 | BBS | 查询某个父评论下的回复 |
| 评论时间线 | BBS | 按时间查询文章所有评论 |
| 最新回复 | BBS | 查询文章最后一条正常评论 |
| 评论点赞 | BBS | 点赞/取消点赞 |
| 评论感谢 | BBS | 感谢/取消感谢，积分服务消费事件处理固定奖励 |
| 评论删除 | BBS、管理端 | 作者删除自己的评论，管理端删除任意评论 |
| 评论治理 | 管理端 | 隐藏、锁定、恢复评论 |

## 3. 不做功能

| 功能 | 原因 |
| --- | --- |
| 评论收藏 | 使用场景弱，容易增加无效复杂度 |
| 评论打赏 | 场景弱，P0 不做 |
| 评论关注 | 没有明确更新语义，不做 |

## 4. 评论结构

| 字段 | 说明 |
| --- | --- |
| `article_id` | 所属文章 |
| `parent_id` | 父级评论；顶级评论为空 |
| `reply_id` | 当前评论直接回复的评论 |
| `level` | 评论层级 |

P0 不新增 `root_id`。现有 `parent_id + reply_id + level` 已能支持当前查询组织，避免增加冗余字段和一致性维护成本。

## 5. 评论创建规则

| 场景 | 规则 |
| --- | --- |
| 文章状态 | 只允许评论 `published + public + none` 文章 |
| 文章评论开关 | `commentable=false` 时不允许评论 |
| archived 文章 | 不允许评论 |
| hidden 文章 | 不允许评论 |
| locked 文章 | 不允许评论 |
| private 文章 | 普通用户不允许评论 |
| 顶级评论 | `parent_id=nil`、`reply_id=nil`、`level=1` |
| 回复评论 | `reply_id` 指向被回复评论，`parent_id` 由被回复评论关系推导 |
| 回复 hidden 评论 | 不允许 |
| 回复 locked 评论 | 不允许 |
| 回复 deleted 评论 | 不允许 |

## 6. 评论状态

| 状态 | 普通用户可见 | 可回复 | 可互动 |
| --- | --- | --- | --- |
| `none` | 是 | 是 | 是 |
| `locked` | 是 | 否 | 否 |
| `hidden` | 否 | 否 | 否 |
| `deleted` | 否，或前端展示占位 | 否 | 否 |

## 7. 查询组织方式

| 查询 | 条件 | 排序 |
| --- | --- | --- |
| 顶级评论线程 | `article_id + level=1` | 热度/时间 |
| 某条评论回复 | `article_id + parent_id` | 时间正序 |
| 评论时间线 | `article_id` | 时间倒序 |
| 最新回复 | `article_id + visible restriction` | 时间倒序取第一条 |
| 用户评论 | `created_by` | 时间倒序 |

## 8. 评论计数

| 操作 | 计数变化 |
| --- | --- |
| 创建评论 | `article.reply_count + 1` |
| 回复顶级评论 | 顶级评论 `reply_count + 1` |
| 作者删除评论 | `article.reply_count - 1`，必要时父评论 `reply_count - 1` |
| 管理删除评论 | `article.reply_count - 1`，必要时父评论 `reply_count - 1` |
| hide/lock | 不修改 reply_count，展示层按状态过滤 |
| restore | 如果删除曾扣减，则恢复时补回计数 |

## 9. 评论互动

| 互动 | 说明 |
| --- | --- |
| like | 评论点赞，表达认可 |
| thank | 评论感谢，触发固定积分奖励事件 |

评论互动使用 `comment_id + user_id + action` 唯一约束，重复操作幂等。

## 10. 删除与治理

| 操作 | 使用方 | 说明 |
| --- | --- | --- |
| 作者删除 | BBS | 作者删除自己的评论 |
| 管理删除 | 管理端 | 管理员删除任意评论 |
| 恢复 | 管理端 | 恢复被删除评论 |
| hide | 管理端 | 普通用户不可见 |
| unhide | 管理端 | 取消隐藏 |
| lock | 管理端 | 可见但不可回复/互动 |
| unlock | 管理端 | 取消锁定 |

## 11. Schema 建议

| 字段类型 | 字段 |
| --- | --- |
| 基础 | `id`、`article_id`、`content` |
| 结构 | `parent_id`、`reply_id`、`level` |
| 状态 | `restriction` |
| 统计 | `like_count`、`thank_count`、`reply_count` |
| 操作人 | `created_by`、`updated_by` |
| 审计 | `created_at`、`updated_at`、`deleted_at` |

## 12. 设计理由

- 评论保留点赞和感谢，去掉收藏/打赏/关注，交互更收敛。
- 感谢和点赞语义不同：点赞是认可，感谢是固定积分奖励事件。
- `parent_id + reply_id` 足够支持楼中楼、时间线、回复目标展示，P0 不加 `root_id`。
- 删除和治理分开：删除是内容生命周期，隐藏/锁定是管理限制。
- hide/lock 不修改评论计数，避免治理动作导致历史统计频繁波动。
