# user 账号凭证表拆分设计说明

## 背景

当前 `account` 表同时保存用户基础资料、登录名、邮箱和手机号。邮箱、手机号属于账号凭证，业务上需要唯一，但当前阶段不调整可空唯一索引，也不修改现有表结构。

## 目标方向

后续可以将账号凭证拆到独立表，例如 `account_credential`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 归属用户 ID |
| `credential_type` | 凭证类型，例如 `name`、`email`、`phone` |
| `credential_value` | 标准化后的凭证值 |
| `verified` | 是否已经验证 |
| `created_at` / `updated_at` | 审计时间 |

唯一约束建议使用：

```text
credential_type + credential_value
```

账号基础资料仍保留在 `account` 表，凭证表只表达可用于认证、绑定和找回的登录凭证。

## 迁移影响

- 需要先回填 `account.name`、`account.email`、`account.phone` 到凭证表，其中邮箱和手机号为空时不生成凭证记录。
- 登录、注册、绑定和解绑逻辑需要从凭证表查询唯一性，不再直接依赖 `account` 表的邮箱和手机号唯一索引。
- 对外模型可以继续返回邮箱和手机号，但读取来源需要明确：可从凭证表按 `user_id` 查询后组装，不把凭证字段继续作为 `account` 表事实来源。
- 迁移期间需要保证双写或停机切换策略，避免新注册账号只写入一侧。
- 索引切换前需要清理历史重复值，并确认邮箱、手机号标准化规则已经固定。

## 当前处理

本次不修改 Ent schema，不调整数据库索引，也不增加迁移脚本。当前文档只记录后续拆分方向和迁移影响。
